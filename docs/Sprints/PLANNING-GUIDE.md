# Sprint planning and completion guide

For a future planned sprint, agree a goal and refine bounded backlog items before implementation. Record actual start/end dates, dependencies, acceptance criteria, and responsible roles only when confirmed. Do not reuse reconstructed records as proof of historical planning.

## Planning

1. Select refined items from the product backlog and state exclusions.
2. Identify dependencies, data/security/operational risks, and required decisions.
3. Define observable acceptance criteria and verification scenarios.
4. Agree realistic scope without inventing capacity or estimates.
5. Create a sprint record using the template and keep pending decisions explicit.

## Completion

Record delivered and incomplete outcomes, exact commits, review links, commands/scenarios, environment, results, skips, and operational handoff. Return unfinished items to the backlog. Review lessons without inventing meeting attendance or stakeholder feedback.
