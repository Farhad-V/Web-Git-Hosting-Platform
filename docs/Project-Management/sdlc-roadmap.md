# SDLC roadmap

The original M0-M7 lifecycle is complete for v1.0.0. New work revisits affected phases rather than claiming the original release evidence validates every later change.

| Phase | New-change activity | Documentation |
| --- | --- | --- |
| Definition | Confirm user problem, scope, constraints, and success criteria | [Project definition](../Project-Definition/project-definition-overview.md) |
| Requirements | Record behavior, permissions, invalid input, and acceptance criteria | [Requirements](../SDLC/Requirements-Engineering/01-requirements-engineering-plan.md) |
| Analysis | Identify state, data flow, and trust boundaries | [Analysis](../SDLC/System-Analysis/01-system-analysis-plan.md) |
| Design | Agree architecture, API, data, UI, and recovery changes | [Design](../SDLC/System-Design/01-system-design-plan.md) |
| Implementation | Deliver focused changes and preserve unrelated data | [Implementation](../SDLC/Implementation/01-implementation-plan.md) |
| Testing | Verify acceptance and affected regressions | [Testing](../SDLC/Testing/01-testing-plan.md) |
| Deployment | Check migrations, workers, health, and rollback | [Deployment](../SDLC/Deployment/04-deployment-runbook.md) |
| Maintenance | Monitor defects, dependencies, backups, and evidence freshness | [Maintenance](../SDLC/Maintenance/01-maintenance-plan.md) |

Use [traceability](traceability.md) to connect outcomes to evidence and [milestone relationships](milestone-sprint-release-relationship.md) to distinguish engineering completion from release publication.
