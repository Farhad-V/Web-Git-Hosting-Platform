# GitForge v2.0.0 — release notes

**Version: v2.0.0.** Tag date: 2026-10-11. Package version: `2.0.0`. The immutable `v2.0.0` tag identifies the release snapshot once pushed. A GitHub Release page is a separate publication step.

## Intended release

This major release introduces permission-only licensing for original project materials and groups the accumulated collaboration, UI and documentation improvements. A major licensing boundary is project policy; it is not an assertion that all existing API contracts break.

## Permission requirements

Prior written permission from Farhad Valizadegan is required to use or reuse original v2 project materials under [LICENSE](../../../LICENSE). Third-party licenses remain applicable, and previous grants are not retroactively revoked. Review the terms before upgrading, running or redistributing these materials. Existing v1 snapshots remain unchanged.

## Features and changes

Repository rename, branch/default management, tags/commit navigation, bounded PDF previews, expandable files, same-repository pull requests/discussions and owner merges, built-in queue-backed Actions, persistent light/dark glass UI, fixed local frontend startup, and expanded organized PlantUML documentation are included. Details and limitations are in the [unreleased overview](UNRELEASED.md) and [changelog](../../../CHANGELOG.md).

## Upgrade and operational requirements

Review the [upgrade guide](UPGRADE-GUIDE.md). Verify paired PostgreSQL/Git backups, migration compatibility, Git version requirements and a dedicated Actions worker before exposing changed features. Rename requires client remote updates. Arbitrary Actions scripts and old-name redirects are not supplied.

## Validation and publication

The five automated workflows passed on preparation commit `deb3447`. Triggered automated checks on the stable-metadata commit must pass before the annotated tag is pushed. Results are recorded in GitHub Actions; outstanding manual acceptance, host supervision and isolated recovery checks remain explicit in the [checklist](RELEASE-CHECKLIST.md). The owner requested creation of this tag. No production deployment or completion of unchecked manual checks is implied.
