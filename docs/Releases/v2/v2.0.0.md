# GitForge v2.0.0 — draft release notes

**DRAFT — UNRELEASED.** Planned version: v2.0.0. Development package version: `2.0.0-dev`. Release date, final commit, tag and GitHub release remain pending.

## Intended release

This planned major release introduces permission-only licensing for original project materials and groups the accumulated collaboration, UI and documentation improvements. A major licensing boundary is project policy; it is not an assertion that all existing API contracts break.

## Permission requirements

Prior written permission from Farhad Valizadegan is required to use or reuse original v2 project materials under [LICENSE](../../../LICENSE). Third-party licenses remain applicable, and previous grants are not retroactively revoked. Review the terms before upgrading, running or redistributing these materials. Existing v1 snapshots remain unchanged.

## Features and changes

Repository rename, branch/default management, tags/commit navigation, bounded PDF previews, expandable files, same-repository pull requests/discussions and owner merges, built-in queue-backed Actions, persistent light/dark glass UI, fixed local frontend startup, and expanded organized PlantUML documentation are planned for inclusion. Details and limitations are in the [unreleased overview](UNRELEASED.md) and [changelog](../../../CHANGELOG.md).

## Upgrade and operational requirements

Review the [upgrade guide](UPGRADE-GUIDE.md). Verify paired PostgreSQL/Git backups, migration compatibility, Git version requirements and a dedicated Actions worker before exposing changed features. Rename requires client remote updates. Arbitrary Actions scripts and old-name redirects are not supplied.

## Validation and publication

Candidate-specific backend, frontend, deployment, dependency, manual UI/Git, recovery and licensing checks remain pending in the [checklist](RELEASE-CHECKLIST.md). Historical passes are not current acceptance. Publish only after selecting and validating the final candidate, aligning stable metadata, finalizing notes and explicitly approving the tag/release.
