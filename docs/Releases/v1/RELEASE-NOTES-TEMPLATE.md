# Release notes template

Copy into a version-specific document only after the version and candidate are agreed. Replace placeholders with confirmed information; leave pending evidence explicit.

## Identity

- Version: pending
- Candidate commit: pending
- Publication date: pending
- State: draft / candidate / published

## User-visible changes

Describe added, changed, fixed, and security-related behavior. Distinguish implemented features from future plans and link relevant contracts.

## Upgrade and compatibility

State dependency/runtime requirements, configuration changes, migrations, worker restarts, client changes, and coordinated backup requirements. Preserve existing secrets and application keys.

## Validation

Record exact commit/environment, commands or scenarios, CI links, outcomes, warnings, skips, and blocked checks. Do not copy earlier totals as current results.

## Known limitations

List unresolved defects, unsupported capabilities, and operational constraints.

## Recovery and publication

Link the approved rollback/recovery procedure. After authorized publication, record tag/commit identity and final release metadata.
